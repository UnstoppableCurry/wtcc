架构

这是进程内的 TypeScript CLI，不是多服务网页。下面按 CLAUDE.md 与目录职责描述；不画未在仓库出现的部署图。

启动与 UI 循环

  1. 用户执行 wtcc → Node shim 定位 Bun → bun run src/entrypoints/cli.tsx。
  2. CLI 引导进入 src/screens/REPL.tsx（Ink / React 终端界面）。
  3. 斜杠命令在 src/commands.ts 注册，实现放在 src/commands/。
  4. 工具在 src/tools.ts 注册，实现放在 src/tools/。
  5. src/QueryEngine.ts 协调消息、tool use 与 model 调用。

路由怎么决策

selectModel（src/routing/router.ts）：

  • 有显式 model（--model / 菜单）时：getModelInfo(id) 做模式推断，来源记为 override，原因 user override。
  • 自动路径：启发式选出 light / medium / heavy，再 getByTier。registry 为空，所以 getByTier 恒为 undefined，会抛 RoutingError，提示必须显式传 --model。

注释写明：上游 getDefaultModel() 通常先填好 override.model，因此自动档在实践中很少走到抛错。 /why-this-model 只展示内存 ring buffer，不保证跨进程持久化。 

src/routing/
  registry.ts      # MODEL_REGISTRY = []；inferProvider / inferTier / context
  heuristics.ts    # 信号 → 档位
  router.ts        # override 优先，否则找 anchor
  pricing.ts       # /cost 用的公开价表
  decisionLog.ts   # /why-this-model
  integration.ts   # 接到主循环

API 与 adapter

  • src/services/api/claude.ts — Anthropic 消息 API
  • src/services/api/claude-openai.ts — OpenAI 兼容流
  • src/services/api/adapter/normalize.ts — 消息互转、孤儿 tool_calls 修补、effort 线上折叠
  • src/services/api/codex-fetch-adapter.ts — Codex responses 形态（vision / tool_result / reasoning delta）
  • src/services/api/relayModels.ts — /v1/models → /model 菜单

i18n

createTranslator 先读当前 locale，缺 key 回退 en-US，再回退 key 本身。支持 {{name}} 插值。zh-CN 与 en-US 目前都是 378 个 key，集合一致。 CONTRIBUTING 要求技术词（token、model、MCP、命令名）不翻译。TODO 仍列出 REPL、Bash 选项、状态栏等未覆盖区域。

Telemetry 边界

src/services/analytics/index.ts 写明：开源构建有意不发产品 telemetry，logEvent / attachAnalyticsSink 为空函数，好让旧调用点继续编译。

树里仍有 growthbook.ts、OTel 相关依赖与上游调用点。本站不把它写成「进程零出站」——只确认对外 analytics API 被做成空操作。GrowthBook 是否在某条实验路径上仍发起网络请求，需要针对具体 build flag 再测。

构建

scripts/build.ts 按 feature flag 打包。默认构建与 build:dev:full 打开的实验集合见 FEATURES.md。许多 flag 能编过但不保证运行时安全（缺原生模块、要 claude.ai OAuth、或外部 @ant/* 包）。
